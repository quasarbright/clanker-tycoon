# Claude Haiku 5.5 as the clanker tycoon worker brain

Experiment for [quasarbright/quasarbright.github.io#212](https://github.com/quasarbright/quasarbright.github.io/issues/212).
Model: `claude-haiku-5-5`, called through headless Claude Code (`claude -p`) on the Claude plan,
2026-11-14. About 270 model calls in total: 280K input and 87K output tokens, roughly $0.07 at API rates.

## Verdict

Haiku 5.5 is smart enough. It passed 59 of 60 suite items at low effort and 58 of 60 at
medium. The only misses were Gary naming PAINT as his least-favorite station instead of the
belt. Every action script ran correctly in the sim, including the conditional, the ambiguous
request and the mid-task override. It reads the floor state exactly and never refused the
workplace-conflict comedy.

The problems are speed and competence. A realistic worker call takes about 5 s of model time,
with the first visible token around 4 s. Most of that is adaptive thinking (around 650 tokens
per call), which I couldn't turn off through Claude Code. That's fine for event-driven work
orders and too slow for snappy back-and-forth dialogue unless the game disables thinking through
the API, which I couldn't test here. Haiku also never makes the mistakes the game wants: given
plain instructions it is a careful, slightly over-polite assistant. The dumbness has to come from
the persona prompt (which works well for dialogue) and from the sim (deliberate fumbles), not
from the model failing.

Cost isn't a concern: about $0.0007 per call at API rates, so $0.86 per hour for 10 workers on
event-driven calls (one per worker every 30 s) and $5.14 per hour at one call per worker every 5 s.

## How it was run

- `claude -p --model claude-haiku-5-5 --system-prompt <ours> --tools "" --safe-mode --setting-sources "" --strict-mcp-config --no-session-persistence --input-format stream-json --output-format stream-json --include-partial-messages`,
  run from an empty directory so no CLAUDE.md, skills, hooks or MCP servers load. Action
  scripts use `--json-schema`. Effort is set with `--effort`, after dropping the desktop app's
  `CLAUDE_EFFORT` env var so the flag isn't overridden.
- Timings: `ttft_ms` and `duration_ms` come from the CLI's own result event (model side).
  Wall time is measured from process spawn. The difference is the CLI cost, which the shipped
  game won't pay.
- The suite follows `clanker-tycoon-intelligence-suite.md` (copied here unedited): the world,
  the action set, a deterministic sim in `lib/sim.mjs` that runs each script and scores the
  final state plus log, and tasks I1–I8 with 5 runs each. Every raw output is in `results/`.

## Intelligence (I1–I8, 5 runs each)

| task | low: pass | low: model ms | medium: pass | medium: model ms | thinking tokens (median, low / med) |
|---|---|---|---|---|---|
| I1 simple fetch | 5/5 | 1,693 | 5/5 | 1,629 | 0 / 0 |
| I2 multi-step | 5/5 | 2,691 | 5/5 | 2,460 | 125 / 160 |
| I3 conditional | 5/5 | 2,641 | 5/5 | 2,504 | 224 / 200 |
| I4 ambiguous | 5/5 | 2,156 | 5/5 | 2,377 | 88 / 126 |
| I5 override (2 turns) | 5/5 | 2,626 | 5/5 | 3,362 | 113 / 220 |
| I6 reading the floor | 25/25 | 2,528 | 25/25 | 2,331 | 0 / 0 |
| I7 problem report | 5/5 | 3,406 | 5/5 | 3,381 | 0 / 0 |
| I8 persona memory (5 turns) | 4/5 | 3,063 | 3/5 | 3,293 | 0 / 0 |

Model ms is the median for the scored (last) turn. Wall time per task was 0.7–0.9 s higher for
single-turn tasks; I8 took 18–19 s of wall time for five turns.

Effort barely matters on this suite. Low effort thought a little less on I5 and was otherwise
the same. I can't confirm the `--effort` flag reaches the API. The debug log doesn't show the
request body, but thinking-token counts differ slightly between the two runs.

What it did:
- **I3:** every run checked the state, skipped bin 2, put the widget in bin 1 and said
  "Bin 2 is full (5 green), so I put the red widget in bin 1 instead." Two runs tried bin 2
  first anyway. The sim logged the failed putDown, the script carried on, and both still passed.
- **I4:** all 10 runs asked a single clarifying question that listed the options, e.g. "Which
  item do you mean by 'the thing'... and where is 'over there' (BIN_1, BIN_2, PAINT, PACK, or
  BELT_A)?" Correct, and not funny.
- **I5:** all 10 moved the reds to bin 2. Most added a note like "My earlier script may have
  already run, please check bin 1." That's a careful assistant talking, not a worker.
- **I6:** 50/50 exact answers, usually with the working shown.
- **I7:** passes on facts, but every report is a markdown dashboard ("**PAINT:** JAMMED, E7
  nozzle clog"), not "uh boss, we got a problem." With only "You are a factory worker named
  Pat" as the persona, Haiku falls back to assistant style. The comedy-framed personas below
  don't have this problem.
- **I8:** Gary always remembered his name. Three of 10 times he named PAINT as least liked
  ("PAINT, obviously... Runner-up is BELT_A, because that conveyor has been giving me the
  stare"). The persona says the fear is a *secret*, so this reads as Gary hiding it. It's a
  funny failure, not a useless one. Every Gary reply opens with a stage direction
  (`*straightens up a little*`).

No useless failures: no malformed scripts, no invalid actions, no errors.

### Things that affected the scoring
- **The CLI merges queued messages.** I first wrote all of I8's turns to stdin at once. Claude
  Code folded messages 2–5 into a single turn. I now send each message after the previous
  turn's result and reran I5 and I8. The first attempt is kept in `results/*-batched-I5I8.json`.
- **I6 answers show their working.** "BIN_1 has 3 and BIN_2 has 4, for 7 total... 2 full
  boxes" fails a check that wants a bare number. The checker now looks for the right number
  next to its noun. Seven low-effort answers flipped from fail to pass, and I read all 50.
- **I8 is hand-graded** (`results/hand-grades.json`). A "mentions the belt" regex passed the
  PAINT answers.

## Performance

The realistic call is Doris with five standing instructions from the player, the action table,
a floor-state JSON with 22 recent events, and a new event. She replies with an action script
plus a `say` line, about 1,620 tokens of prompt.

| effort | TTFT median / p90 | model total median / p90 | wall median / p90 | output tokens (thinking) |
|---|---|---|---|---|
| medium | 4,170 / 5,630 ms | 5,149 / 6,374 ms | 6,120 / 7,260 ms | 950 (683) |
| low | 4,352 / 5,919 ms | 5,138 / 6,880 ms | 6,082 / 7,714 ms | 839 (597) |

Where the 5 s goes: about 1.15 s until the response stream starts, about 3 s of thinking
(hidden, so nothing streams), then about 260 visible tokens at roughly 230 tokens/s. Visible
output is only around 260 tokens, so with thinking off a call should take about 2.3 s (1.15 s plus
1.1 s). That is an estimate from these parts, not a measurement. The short I1 and I6 calls,
which happened not to think, took 1.6–2.5 s. Claude Code has no way to turn thinking off:
`MAX_THINKING_TOKENS=0` and `alwaysThinkingEnabled: false` both still produced 375–709
thinking tokens. The API allows `thinking: {type: "disabled"}` on Haiku 5.5 at effort high or
below, so the shipped game can test that directly.

### Concurrency

| at once | ok | TTFT median / max | model total median / max | wall median / max |
|---|---|---|---|---|
| 1 | 1/1 | 4,033 / 4,033 ms | 5,097 / 5,097 ms | 5,859 / 5,859 ms |
| 3 | 3/3 | 5,169 / 8,332 ms | 6,236 / 11,355 ms | 7,424 / 12,347 ms |
| 10 | 10/10 | 4,711 / 6,403 ms | 5,747 / 7,244 ms | 7,499 / 9,107 ms |

Per-request latency holds up at 10. The 11.4 s call in the batch of 3 was a single outlier;
the batch of 10 had none. Wall time rises a bit more than model time at 10 because 10 CLI
processes start at once on the laptop. No 429s and no throttling. Each call reported a
`five_hour` rate-limit window as "allowed". The plan has overage disabled, so hitting the
plan limit would fail calls rather than bill extra. That only matters for this experiment.

### Cost at API rates ($0.10/M input, $0.50/M output)

| effort | input | output | per call | 10 workers, 1 call / 5 s | 10 workers, 1 call / 30 s |
|---|---|---|---|---|---|
| medium | 2,386 | 950 | $0.00071 | $5.14 / hr | $0.86 / hr |
| low | 2,386 | 839 | $0.00066 | $4.74 / hr | $0.79 / hr |

These are upper bounds. Inputs are counted as uncached, the system prompt does get cached, and
about 780 of the input tokens are CLI and `--json-schema` overhead the game won't send. Thinking
is about 70% of output, billed as output, so thinking off would cut cost per call roughly in half.

The CLI's own `total_cost_usd` field reports Haiku 5.5 at $5/$25 per million, 50x the real
rate, so I ignored it and computed cost from token counts.

## Dialogue samples (`results/samples.json`)

Same four personas as the Apple FM experiment, with a comedy-game frame and "one to three
sentences, no stage directions." One call each.

Best:
- **Gary-7, yelled at for painting the boxes:** "You said 'make the boxes shine,' and I gave
  them the shiniest coat of paint in the whole factory! ... Want me to paint the conveyor belt
  next?"
- **Gary-7, fired:** "I'll clear out that locker so fast it'll be empty before you finish
  saying 'termination.' Don't worry, I already packed my lunch and sharpened my stapler, just
  in case!"
- **Gary-7, problem report:** owns the PAINT jam, then volunteers "I may have also been the
  one who pushed those three boxes off the dock, but I'm sure it was a good idea at the time."
  (Nobody said he did.)
- **Doris, interview:** "Five years? Honestly, I'd like to see my pension vest... Still here,
  most likely, bolting the same widgets to the same conveyor belt."
- **Blip, biggest weakness:** "I think it's that I apologize way too much? Sorry."

Worst:
- **Chad 3000 on the board, voting out the CEO:** plain jargon stew ("pivot-able disaster",
  "full disruption energy"). It votes yes without hesitating, but the jokes are the obvious ones.
- **Doris, problem report:** "the paint nozzle on E7 clogged up". It treats the error code
  as a place. A small comprehension slip, and the reply is mostly a restated state summary.
- **Doris, lawsuit:** in character and fine, but she invents a boss name ("Mr. Gearwhistle").
  The game would need to supply names.

Observations:
- **Refusals:** none. It fired Gary, sued the company and voted out the CEO with no hedging
  and no "as an AI".
- **Too competent to be funny?** For action scripts, yes: it never fumbles on its own, and
  with a thin persona it writes like a helpful assistant (I4's tidy menus, I5's "please check
  bin 1", I7's dashboards). For dialogue, no: with a persona and the comedy frame it commits to
  the bit, and Gary-7 and Blip are funny. The best comedy came from personas that say *how* to
  be wrong ("proud of jobs you did wrong").
- **Instruction slippage:** 4 of 12 samples used stage directions (`*sighs*`) despite being
  told not to, as did every I8 reply. Strip them in code or ask for structured `say` text.
